# 编译真相 + 时间线模式

## 目标

每个大脑页面有两个区域：编译真相（当前综合，随证据变化重写）和时间线（仅追加的证据轨迹，永不编辑）。

## 用户获得的价值

没有这个：大脑页面是仅追加的日志。要了解一个人，你需要阅读200条时间线条目。答案隐藏在第147条中。

有了这个：编译真相在30秒内告诉你当前状态。时间线是证据。六个月的条目压缩成一段始终最新的评估段落。

### 更新页面

```
update_brain_page(slug, new_info, source):
  page = gbrain get {slug}

  // 时间线：始终追加（从不编辑现有条目）
  gbrain add_timeline_entry {slug} {
    date: today,
    summary: new_info.summary,
    detail: new_info.detail,
    source: format_source(source)  // [来源: 谁, 渠道, 日期时间时区]
  }

  // 编译真相：重写（不是追加）
  // 读取现有的编译真相
  // 整合新信息
  // 写入更新后的综合
  updated_truth = rewrite_compiled_truth(page.compiled_truth, new_info)
  gbrain put {slug} {
    compiled_truth: updated_truth,
    // 时间线不传递 —— 由 add_timeline_entry 管理
  }
```

### 规则

| 区域 | 操作 | 解释 |
|------|------|------|
| 编译真相 | **重写** | 当前综合。证据改变时改变。 |
| 时间线 | **追加** | 证据轨迹。从不编辑，只添加。 |

**每个编译真相主张必须追溯到时间线条目。** 如果评估说"内部被低估"，应该有支持该主张的时间线条目。

## 需要注意的地方

1. **重写意味着重写，不是追加。** 不要在编译真相中添加新段落。用整合的新信息重写整个部分。不再准确的旧评估应该更新，而不是与矛盾的新评估并存。

2. **时间线条目是不可变的。** 永远不要编辑时间线条目。如果信息被证明是错误的，添加一个新条目来更正：
   `- 2026-04-10 | 更正：Sarah是VP Eng，不是CTO。之前的条目错误。`

3. **GBrain搜索给予编译真相更高权重。** `gbrain query` 返回编译真相块的相关性高于时间线块。这意味着最新的综合在搜索结果中首先显示。

4. **---分隔符很重要。** GBrain使用frontmatter后的第一个独立`---`来分隔编译真相和时间线。上面的所有内容都是编译真相，下面的所有内容都是时间线。

5. **不要跳过评估部分。** 评估是价值所在。"强大的技术领导者"是任何API都无法提供的。这是你对这个人的看法。这就是为什么大脑页面比LinkedIn更好。

## 验证方法

1. **更新人物页面。** 添加新会议信息。检查：编译真相被重写（不是追加），时间线在顶部有新条目。
2. **搜索该人物。** `gbrain query "Sarah Chen"`。编译真相（当前综合）应该首先出现，而不是随机的时间线条目。
3. **检查可追溯性。** 编译真相中的每个主张都应该有相应的时间线条目。阅读两个部分并验证。
4. **检查不变性。** 更新后，旧的时间线条目应该保持不变。日期、来源和内容应与原始完全匹配。
