# 技能开发生命周期

## 目标

将每个重复任务转化为持久的自动化技能，这样如果你问两次，它应该已经在 cron 上运行了。

## 用户获得的价值

没有这个：临时工作，代理会忘记如何做。你问"丰富这个人"，代理每次都发明新流程。质量参差不齐。

有了这个：每个能力都被编码、测试和调度。丰富化每次都以相同方式运行。新模式在一天内被技能化。

## 实现方案

**规则：** 如果你必须向代理询问某事两次，它应该已经是一个在 cron 上运行的技能。第一次是发现。第二次是系统故障。

### 五步循环

**步骤1：构思流程。**
用简单语言描述需要发生什么：
- 输入是什么？输出是什么？触发条件是什么？
- 它触及哪些数据源？
- 应该多久运行一次？

**步骤2：手动运行3-10个项目。**
在一小批数据上手动完成工作。这是原型阶段。**不要**写 SKILL.md。只需完成工作并观察：
- 输出实际是什么样子？
- 出现了哪些边缘情况？
- 什么样的质量标准是合适的？

**步骤3：评估输出。**
向用户展示结果。获取反馈。
- 输出看起来好吗？质量合适吗？
- 你遗漏了什么？过度设计了吗？
- 根据学到的内容修订流程。

**步骤4：编码为技能。**
编写 SKILL.md。要么：
- **新技能** -- 真正新的能力
- **添加到现有技能** -- 现有技能的变体（参数化）

技能必须：
- **持久** -- 明天、下周、下个月无需人工干预即可工作
- **MECE** -- 不与其他技能重叠（见下文）
- **参数化** -- 通过参数处理变体，而不是单独的技能

**步骤5：添加到 Cron（如果重复）。**
如果流程应该自动运行：
- 如果自然适合，添加到现有的 cron 任务
- 如果有明显的调度问题，创建新的 cron 任务
- 监控前2-3次自动运行的质量
- 修复大规模出现的问题

### MECE 规范

技能应该是**相互排斥、完全穷尽**的：
- 每种实体类型恰好有一个所有者技能
- 每个信号源恰好有一个所有者技能
- 两个技能创建同一个大脑页面 = MECE 违规

**所有权示例（无重叠）：**

| 信号源 | 所有者技能 | 创建 |
|--------|-----------|------|
| 会议记录 | meeting-ingestion | brain/meetings/ 页面 |
| 电子邮件 | executive-assistant | brain/people/ 时间线条目 |
| X/Twitter 帖子 | x-collector | brain/media/ 页面 |
| 人物丰富化 | enrich | brain/people/ 编译真相 |
| 日历事件 | calendar-sync | brain/daily/calendar/ 页面 |
| 视频/播客内容 | media-ingest | brain/media/ 页面 |

### 质量标准清单

技能准备就绪时：

- [ ] 在 3-10 个真实项目上成功运行，输出良好
- [ ] 用户审查输出并批准
- [ ] SKILL.md 少于 500 行（使用引用处理溢出）
- [ ] 在创建大脑页面之前检查知名度（不为无关人员创建页面）
- [ ] 有引用强制执行（每个事实都有来源）
- [ ] 不与现有技能重叠（MECE）
- [ ] 如果重复：在 cron 上有适当的调度
- [ ] 如果创建大脑页面：首先检查知名度

### 实际意义

- 不要进行临时大脑丰富化，使用 enrich 技能
- 不要手动检查社交媒体，使用自动 cron
- 不要手动摄取会议笔记，使用 meeting-sync 配方
- 不要手动创建实体页面，使用实体检测器
- 如果出现新模式，原型化它，技能化它，cron化它

## 难点

1. **MECE 违规会静默复合。** 两个都创建 `brain/people/` 页面的技能将产生重复和冲突的数据。在创建新技能之前，检查所有权表。如果现有技能已经拥有该实体类型，请使用参数扩展它，而不是创建新技能。

2. **质量标准是真实的。** 不要发布未经 3-10 个真实项目测试且未经用户批准的技能。产生不良输出的技能比没有技能更糟糕——它会在 cron 上大规模创建不良大脑页面。

3. **不要创建存根。** 带有"TODO: implement"的 SKILL.md 不是技能。每个技能必须足够完整，可以在真实数据上端到端运行。如果你无法完成它，不要创建文件。在你能正确完成之前，保持手动工作。

## 验证方法

1. **在 3 个真实项目上运行技能。** 对实时数据（不是测试数据）执行技能。检查输出是否符合质量标准：存在引用、检查知名度、未创建存根。

2. **检查与现有技能的 MECE。** 查看所有权表。这个新技能是否在另一个技能已经拥有的目录中创建页面？如果是，这是 MECE 违规。改为合并或参数化。

3. **验证质量标准清单。** 查看上面的质量标准清单中的每一项。如果任何项目未勾选，该技能不适合 cron 部署。
