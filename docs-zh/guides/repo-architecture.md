# 双仓库架构：代理行为与世界知识

## 目标

将代理行为（可替换）与世界知识（永久）分离到两个具有严格边界的仓库中。

## 用户获得的价值

没有这个架构：代理配置和世界知识混合在一起。切换代理会丢失知识。切换知识工具会丢失代理设置。

有了这个架构：你的大脑（14,700+ 文件的人物、公司、会议、想法）在任何代理更换后都能保留。你的代理配置在任何知识工具更换后都能保留。

## 实现方案

### 边界测试

**"这是关于代理如何运作，还是关于世界的知识？"**

| 问题 | 如果是 -> 代理仓库 | 如果是 -> 大脑仓库 |
|------|-------------------|-------------------|
| 切换 AI 代理时此文件会迁移吗？ | 是 | -- |
| 切换到另一个人时此文件会迁移吗？ | -- | 是 |
| 这是关于代理行为的吗？ | 是 | -- |
| 这是关于人物、公司、交易、会议或想法的吗？ | -- | 是 |

### 快速决策树

```
要创建新文件？
  |-- 关于人物、公司、交易、项目、会议、想法？ -> brain/
  |-- 规格、研究文档或战略分析？ -> brain/
  |-- 原创想法或观察？ -> brain/originals/
  |-- 每日会话日志或心跳状态？ -> agent-repo/
  |-- 技能、配置、cron 或 ops 文件？ -> agent-repo/
  |-- 任务或待办事项？ -> agent-repo/tasks/
```

### 硬性规则

**永远不要将知识写入代理仓库。** 如果技能、子代理或 cron 任务需要创建关于人物、公司、交易、会议、项目或想法的文件，它必须写入大脑仓库，而不是代理仓库。

大脑是永久记录。代理仓库是可替换的。

### 为什么需要两个仓库

**独立性。** 你可以切换 AI 代理（OpenClaw -> Hermes -> 自定义）而不会丢失知识。你可以切换知识工具（GBrain -> 其他工具）而不会丢失代理设置。

**规模。** 大脑会变大（10,000+ 文件）。代理仓库保持小（< 100 文件）。不同的备份策略，不同的同步节奏。

**隐私。** 大脑包含敏感信息（人物、交易、个人笔记）。代理仓库包含操作配置。不同的访问控制。

**GBrain 索引大脑仓库。** 运行 `gbrain sync --repo ~/brain/` 保持搜索索引最新。代理仓库永远不会被 GBrain 索引。

## 难点

1. **永远不要将知识写入代理仓库。** 这是最常见的违规。创建人物页面的技能、保存会议笔记的 cron 任务、捕获想法的子代理 — 所有这些都必须写入大脑仓库。如果是关于世界的，就放入大脑。

2. **大脑是永久记录。** 有疑问时，问："切换到完全不同的 AI 代理后，这个文件会保留吗？" 如果是，它属于大脑。代理配置、技能、cron 任务和操作状态是可替换的。人物、公司、想法和会议不是。

3. **不要索引代理仓库。** GBrain 只索引大脑仓库。对代理仓库运行 `gbrain sync` 会用操作配置污染搜索结果，而不是世界知识。

## 验证方法

1. **检查文件放置。** 任何技能或 cron 任务创建文件后，验证它是否放在正确的仓库中。人物/公司/想法/会议文件应在 `brain/` 中。技能/配置/cron/状态文件应在代理仓库中。代理仓库中的任何知识文件都是边界违规。

2. **运行边界测试。** 选择 5 个最近创建的文件，问："如果我切换 AI 代理，这个会迁移吗？" 和 "如果我切换到另一个人，这个会迁移吗？" 如果答案与文件位置不匹配，它就在错误的仓库中。

3. **验证 GBrain 只索引大脑。** 运行 `gbrain stats` 并检查索引路径。没有一个应该指向代理仓库目录。如果代理配置文件出现在搜索结果中，同步目标配置错误。
